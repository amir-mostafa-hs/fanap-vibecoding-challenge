# Bazarcheh Support Triage System — Engineering Writeup

## 1. What I Understood the Real Problem to Be
Sara and her support team at Bazarcheh handle large volumes of inquiries in Persian, English, and Finglish across multiple communication channels. The core challenge is twofold:
1. **Accurate Prioritization and Trustworthy Numbers:** Sara needs to immediately see what issues customers are facing (broken down into 6 canonical categories) and prioritize high-severity inquiries that risk breaching or have already breached the 2-business-hour SLA promise.
2. **Operational Safety and Efficiency:** The team must be equipped to draft quick replies without risking unauthorized financial or delivery commitments, while operating within strict LLM quota boundaries.

## 2. Assumptions Made
- **Working Calendar:** Business hours are Saturday to Wednesday, 09:00–17:00 Asia/Tehran (UTC+03:30). Thursdays and Fridays are weekend days. Official Iranian public holidays for Solar Hijri year 1405 (26 dates in March 2026–March 2027) are non-working days.
- **SLA Promise:** The urgent threshold is exactly 2.0 business hours elapsed since receipt on an unanswered, canonical high-severity message.
- **Deduplication:** When a customer sends the same message body multiple times, only the earliest message is canonical; subsequent resends do not increment urgency counts or report totals.
- **Order Numbers:** Order numbers follow `BZ-<digits>`, where digits may be written in Latin (`0-9`), Persian (`۰-۹`), or Arabic (`٠-٩`) numerals.

## 3. What Was Wrong in the Existing Code and How I Found Each Problem
- **Western Calendar & UTC Assumption:** In `app/sla.py`, business days were defined as Monday–Friday (`{0, 1, 2, 3, 4}`) in UTC. Found by inspecting code and comparing against `README.md` which specified Saturday–Wednesday in Tehran time.
- **Ignored Public Holidays:** No holiday logic existed in `app/sla.py`. Found by inspecting the SLA arithmetic functions.
- **Misconfigured SLA Hours:** `docker-compose.yml` set `URGENT_SLA_BUSINESS_HOURS="24"`, contradicting Sara's 2-hour promise. Found by reviewing service configurations.
- **Missing Persian Digit Extraction:** `app/orders.py` used regex `BZ-([0-9]+)`, which failed to match Persian numbers like `BZ-۴۸۲۱۹`. Diagnosed by running unit tests on Persian strings.
- **Excessive Quota Depletion on Upload:** `app/api.py` passed `prefetch_drafts=True` on every upload, exhausting LLM quota in advance. Found by tracing upload handler logic.
- **Inflexible Temperature Parameter:** Fixed `temperature=0` crashed modern LLM endpoints (e.g. OpenAI o-series / Luna) with HTTP 400 Bad Request. Diagnosed via direct endpoint inspection.
- **Missing Safety Guardrails & LTR Interface:** The frontend was in English and LTR with no RTL layout; automated draft replies lacked safety checks for money and dates; and QA contract test hooks (`draft-text` as textarea, `draft-approve`, `draft-warning`) were absent or incorrect.

## 4. What Was Cut and Why
- **Automatic Draft Prefetching:** Completely removed prefetching during file upload to strictly honor Sara's quota and on-demand clicking requirement.
- **Serial 1-by-1 Classification:** Replaced single-item classification with batch chunking (20 messages per request) combined with robust rule-based fallback, cutting network overhead and latency by ~95%.
- **Complex Timezone Libraries:** Avoided external runtime timezone packages by defining explicit UTC+03:30 offsets and exact 1405 Gregorian date mappings, preventing version or database drift.

## 5. Where the AI Misled
- The legacy code generated by previous AI tools made standard Western assumptions (Monday–Friday work week, UTC-based arithmetic) and assumed wall-clock countdowns in the browser frontend rather than calculating business SLA minutes.
- When generating reply drafts, naive LLM completions tend to be overly apologetic and frequently make unauthorized promises (e.g., "We will refund your 50,000 Tomans within 2 days"). This required adding deterministic post-generation safety validators.

## 6. How I Know the LLM Classification Is Good Enough
- Messages are first cleaned and normalized.
- The LLM prompt restricts output to the strict 6 canonical categories and valid JSON schemas.
- If the LLM produces an unrecognized category, invalid JSON, or fails network connectivity, it automatically falls back to an extensive domain keyword dictionary covering Persian, English, and Finglish terminology.

## 7. How I Made Sure AI-Written Replies Are Safe to Show Sara
- **Prompt Guardrails:** The system prompt explicitly forbids the model from promising refunds, mentioning monetary values, or giving specific dates and deadlines.
- **Post-Generation Validator:** Every draft is scanned with regular expressions for monetary terms (`تومان`, `ریال`, `$`, `refund`, `reimburse`) and delivery/date promises (`تا فردا`, `ظرف ... روز`, `by tomorrow`).
- **Fail-Safe Blocking:** If any unsafe pattern is detected, or if the LLM is unreachable, the API returns HTTP 200 with `blocked: true` and clear warnings.
- **Human-in-the-Loop:** Drafts are presented in an editable textarea; nothing is ever sent directly without Sara reviewing and approving the copy.
